# Naliv delivery: local development map

- Work on the **active feature route** (`lib/features/*`) and inspect `lib/widgets/authentication_wrapper.dart` before changing a screen. `lib/pages/*` includes legacy destinations; do not silently replace them or invent API contracts. Whole-app scope and ordered milestones: `docs/redesign/PLAN.md`; implementation evidence: `docs/redesign/STATUS.md`.
- The production API and personal account are read-only during verification. Never send SMS, mutate addresses/cards, create orders, or execute payments. Fixture transports must reject unexpected requests; do not silently fall through to production.
- Design reference is a 375 × 812 logical-pixel viewport with 48 px top/34 px bottom insets. Figma frame exports and specs are under ignored `.figma_cache/shots/` and `.figma_cache/spec/`. Preserve dark/light themes and the floating cart-only navigation.
- Before a UI milestone, list visible controls, their destination, loading/empty/error states, and data source. Prove the active route and its interactions in a deterministic fixture, then review visual geometry; a pixel match alone does not prove usability.
- Development surfaces: `flutter run -d windows -t tool/dev_surface.dart` (fixture-only; select screens in its UI). The Windows CMake project stages third-party plugin installers separately so debug launch and hot reload work. Screenshot and diff: `dart run tool/verify_surface.dart <home|catalog|all_products|cart|profile|all> --theme dark|light|both`. If a matching export is absent, run `dart run tool/figma_spec.dart png --page "Design System (Light)" --frame "<exact Figma frame>"` with local Figma credentials; cached PNGs under `.figma_cache/` are ignored. Diff metrics compare **synthetic fixture content**; neither these fixtures nor a pixel match prove authenticated production behavior.
- VS Code has a `Design fixtures (Windows)` launch configuration plus Tasks for capture/diff, full tests, and analysis. Use the fixture launch for hot reload; the older Chrome debug configuration is retained for legacy use, not the default here.
- Verify a changed path with focused tests, then run `flutter test` and `dart analyze lib test tool` at integration. Build tracked web output with `flutter build web --release --no-wasm-dry-run` only after code settles; smoke the release build at 375 × 812. In OMP browser tabs explicitly call `tab.run(async ({page}) => page.setViewport({width: 375, height: 812, deviceScaleFactor: 2}))` before screenshots: its default DPI on this workstation is 1.25, while Figma exports are 750 × 1624 px. Debug Chrome DDC previously crashed on this Windows workstation; do not retry it without a relevant change.
- The runtime Dart MCP server in `.omp/mcp.json` only connects to a running debug Flutter app. OMP LSP handles definitions/references. Runtime tools are development-only; they do not inspect a release web bundle.
