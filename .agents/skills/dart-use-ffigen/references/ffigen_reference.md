# Versioned ffigen reference

## Check the generator before copying an API

The exact resolved release, not the latest online example, defines the API.
ffigen 20.1.1 declares Dart >=3.8 and exposes `FfiGenerator(headers:, functions:,
output:)`, `Headers`, `Functions` and `Output(dartFile:)`. Newer upstream examples
may use `Input`, `Visitor` and `DartOutput` instead. A working pinned YAML flow
need not migrate for a one-function extension; follow that release's supported
configuration and existing generation command.

Two parameters formerly shown in this skill are **not in ffigen 20.1.1**:

- `Functions(recordUse: ...)`.
- `Output(recordUseMapping: ...)`.

Do not invent them or add usage-recording to ordinary runtime binding tasks.
For deliberate native link-time optimization, consult a compatible SDK/generator
and mapping implementation as a separate integration concern.

## Example: sqlite3_libversion with ffigen 20.1.1

This preserves the original single-function/header example while making the
version and binding style explicit. It is a reference for a package that already
owns SQLite sources, not scaffolding to add to a Flutter app.

Example `third_party/sqlite/sqlite3.h`:

```c
// The author disclaims copyright to this source code.
#ifndef SQLITE3_H_
#define SQLITE3_H_

const char *sqlite3_libversion(void);

#endif // SQLITE3_H_
```

Example `tool/ffigen.dart`, using **20.1.1** APIs:

```dart
import 'dart:io';
import 'package:ffigen/ffigen.dart';

void main() {
  final root = Platform.script.resolve('../');
  FfiGenerator(
    headers: Headers(
      entryPoints: [root.resolve('third_party/sqlite/sqlite3.h')],
    ),
    functions: Functions(
      include: (decl) => decl.originalName == 'sqlite3_libversion',
    ),
    output: Output(
      dartFile: root.resolve('lib/src/third_party/sqlite3.g.dart'),
      style: const DynamicLibraryBindings(wrapperName: 'SQLiteBindings'),
      format: true,
      preamble: '''
// The author disclaims copyright to this source code.
// Generated by package:ffigen. Do not edit manually.
// Regenerate: dart run tool/ffigen.dart
''',
    ),
  ).generate();
}
```

`DynamicLibraryBindings` generates a wrapper that accepts a `DynamicLibrary` or
lookup function. Retain the owning package's actual loader. The alternative
`NativeExternalBindings` style emits `@Native` declarations and requires the
corresponding native symbol/asset resolution; it does not package the library.
Do not change loading strategies just to copy this example.

The disclaimer above belongs to the displayed example header. For real headers,
use the real applicable notices, not the Dart project authors' copyright copied
from a template. Layout and filename choices are package conventions.

## Targeted configuration

- `Headers.entryPoints`: actual header URIs, resolved package-relatively.
- `Headers.include`: transitive-header filter; don't exclude required types.
- `Headers.compilerOptions`: include/define/target flags matching the binary ABI.
- `Functions.include`: positive predicate for intended public entrypoints.
- `Functions.isLeaf`: only for genuinely short native calls without Dart callbacks.
- `Output.preamble`: generation warning, applicable notices, any specific justified
  generated-name lints. Avoid `ignore_for_file: type=lint` as a blanket default.
- `Output.format`: controls formatting for this release; follow existing tooling.

For declarations absent from generated output, inspect both header and declaration
filters plus conditional compilation. For failed parsing, inspect libclang,
include paths, target SDK and defines. Do not blanket-ignore source errors.

## Verification when changing bindings

Run the existing generation command (this example uses `dart run tool/ffigen.dart`),
review its output diff and run package-appropriate analysis/tests. An analyzer
error can be a wrong SDK, stale output or configuration error, not automatically a
generator defect. Fix the input/configuration and regenerate. Escalate with a
minimal header, configuration, exact versions and diagnostics only when warranted.
Never hand-edit output or suppress real errors. Native loading/symbol/export and
calling-convention tests remain separate from successful generation.
