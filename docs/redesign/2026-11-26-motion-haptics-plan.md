# План: движение и тактильный отклик «Градусы24»

Решение: на Samsung приняты B для первого добавления, количества и ручного выбора категории. Остальные изменения объединены в один офлайн-пилот без A/B и без публикации.

**Цель:** дать почувствовать, что действие принято, не превращая покупку в цепочку вибраций. Фирменный момент — первое добавление: товар попадает в корзину, крышка раскрывает сумму, палец получает один мягкий ответ. Остальные действия тише. Критерий — понятнее ли результат, а не сколько эффектов добавлено.

## Что уже есть

- `lib/design/motion.dart`, `lib/ui/motion_widgets.dart`: реакция на прижатие с отменой при скролле, смена состояния, смена числа с направлением, короткий акцент на счётчике и моментальное состояние при Reduce Motion. Не создавать второй набор длительностей или кривых.
- `lib/ui/app_cart_button.dart`: плашка суммы уже раскрывается за крышкой; сумма меняется, счётчик реагирует на рост. `lib/ui/product_card.dart` уже анимирует переход к степперу. Не добавлять одновременно прыжок корзины, вспышку карточки и перелёт товара.
- Из явных вызовов тактильного API найдены `lightImpact` после добавления из `ProductPage._addToCart` и `heavyImpact` при `OtpCodeField.errorShake`. В `login_page.dart` один путь объединяет неверный код и неудачный запрос: сильный удар сейчас не означает достоверно «вы ошиблись». Отдельно проверить встроенный отклик Material-контролов на устройстве — текстовый поиск его не измеряет.
- `CartProvider.incrementCatalogItem` / `decrementCatalogItem` возвращают `void`; касание не гарантирует изменения (остатки, ограничения магазина, варианты). В `cart_page.dart` уже есть удаление с сохранением строки и «Вернуть». Не менять эти правила ради анимации.

## 1. Пилот: почувствовать первое добавление

- [x] В одной офлайн release-фикстуре: A — текущий визуал без вибрации, B — тот же визуал и один `HapticFeedback.lightImpact()` после перехода позиции из 0 в положительное количество. Пауза и положение крышки не меняются. Поверхности: карточка каталога и простой экран товара.
- [x] `lib/ui/app_haptics.dart` использует системный API Android/iOS без нового плагина или разрешения; на web/desktop остаётся визуальный результат. Корзина не ждёт ответа платформы.
- [x] Один обработчик принятого пользовательского действия сравнивает количество по существующему ключу до и после изменения. `CartProvider`, анимации и восстановление корзины тактильный сигнал не вызывают. Конфигуратор не входит в пилот.
- [x] `catalog_flow_test.dart`, `product_promotion_card_test.dart`, `first_add_pilot_test.dart`: одно принятое первое добавление — один вызов; повторный плюс, переход в корзину, перетаскивание, отказ и загрузка непустой корзины — ноль новых вызовов.
- [x] На Samsung SM-S938B сравнили A и B: пользователь выбрал B. Мягкий системный импульс на первое принятое добавление остаётся в обоих вариантах следующего эксперимента.

Реализация пилота: в меню фикстуры выберите A или B, затем **Каталог** или **Карточка товара**. Варианты используют одни и те же страницы; **К выбору** позволяет начать следующий опыт с пустой корзиной. Видимый результат добавления и число вызовов платформы проверяют `first_add_pilot_test.dart`, `catalog_flow_test.dart` и `product_promotion_card_test.dart`. Это не измерение вибрации рукой. Отдельная кнопка **Открыть вход** проверяет возврат к частично введённому коду WhatsApp на синтетическом номере — без отправки сообщений.

## 2. Довести корзину и выбор до единого поведения

- [x] Принятое первое добавление использует один `lightImpact`: главная, каталог, поиск, избранное, промо, рекомендации и карточка товара. В конфигураторе отклик привязан к сохранённому изменению, а не к касаниям в черновике.
- [x] Пользователь выбрал B: первое добавление даёт `lightImpact`, дальнейшие принятые изменения количества — `selectionClick` в обычном приложении. Интервал 90 мс ограничивает только щелчки, без очереди и задержки изменений корзины.
- [x] Строка меняется на «Удалено · … / Вернуть» на своём месте (`AppMotion.swap`, 180 мс, без анимации при Reduce Motion). Только входящая строка доступна для нажатия и диктора; возврат восстанавливает исходные варианты и объём.
- [x] Целевые проверки покрывают дробный шаг, остаток, быстрые нажатия, удаление, возврат, 2× текст и координаты соседней строки. На Samsung SM-S938B в автономном каталоге собрано 10 разных товаров на 7 250 ₸. После удаления тоника — 6 750 ₸, после «Вернуть» — снова 7 250 ₸; координаты следующего товара не изменились. Журнал Android: первый импульс есть в A и B; повторный `+` в A без импульса, в B `+`, `−`, удаление и возврат дали по одному системному щелчку.

## 3. Точечные акценты вне корзины

- [x] **Избранное:** один щелчок на подтверждённое сервером изменение. `false` — снято, `null` или некорректный ответ — без сигнала. Уход со страницы, фоновый режим и смена аккаунта во время запроса гасят запоздалый отклик. Проверки: `favorites_membership_test.dart`, `liked_session_ownership_test.dart`.
- [x] **Проверка кода WhatsApp:** при неоднозначной ошибке поле не трясётся и не даёт тактильного сигнала. Доступный для диктора текст предлагает ввести код ещё раз, не обвиняя пользователя в ошибке.
- [x] **Категория:** принятый вариант B включён в обычном приложении. Щелчок подтверждает ручной выбор другой категории, но не прокрутку, автоматическую подсветку или повторное нажатие.

Корзина и верх стекла опущены вместе на 4 логических пикселя, размер кнопки и системный нижний отступ сохранены. На одинаковых кадрах Samsung SM-S938B (450 dpi) край значка и край стекла сместились вниз на 11 физических пикселей. Каталог отрисован также в обеих темах фикстуры.

На Samsung в отдельном офлайн-APK: при выборе «Вино → Пиво» журнал вибрации пуст в A, в B зарегистрирован один `CLOCK_TICK`, повторное нажатие на выбранную категорию без отклика. Добавление и снятие сердца — по одному `CLOCK_TICK`; синтетический отказ проверки кода показал текст без вибрации.

## 4. Управление и проверка перед включением

- [x] «Тактильный отклик» рядом с темой доступен гостю и вошедшему на Android/iOS. Настройка устройства (`SharedPreferencesAsync`) не зависит от аккаунта. До загрузки мотор молчит, при отключении останавливаются и поздние подтверждения; переключатель не проигрывает пример.
- [ ] **Reduce Motion и тактильность независимы**: движение при выключенных анимациях сразу переходит в конечное состояние; отказ от вибрации не отключает визуальное подтверждение. Вибрация никогда не единственный носитель информации. Сохранить текст, семантику, фокус, области нажатия ≥44 px, светлую/тёмную темы, дробные единицы и поведение гостя.
- [ ] **Бюджет:** не менять сплэш, blur/шейдеры дока, маршрутизацию, хранение корзины и покупательские API. Без звуков, бесконечных пульсаций, конфетти, вибрации на сеть/автообновление и «успеха» при нажатии «Оплатить». Без фонового таймера. Анимация только у элемента, состояние которого изменилось.
- [ ] **Приёмка:** `dart run tool/design_harness.dart check <затронутые тесты>`, затем release A/B на Samsung: первый товар, серия `+/-`, скролл карточек, удалить/вернуть, ошибка и уход со страницы. Сравнить UI/raster p90 и кадры за бюджетом дисплея при одинаковой сцене и прогретых ресурсах (8,33 мс на 120 Гц); замер не заменяет оценку ощущений рукой. На iPhone проверить физически, если доступен; эмулятор и видео не доказывают тактильность. Проверить режим «без вибрации» на устройстве и web без платформенных вызовов. Только фикстуры, без заказов, оплаты и действий с личным аккаунтом. Итог: локальный APK, краткое видео визуальных переходов, список реально проверенных устройств; без публикации.

**Единый пилот:** «Пройти покупку» использует боевые экраны с изолированным тестовым транспортом. Отдельные входы дают проверить адреса, восстановление после отказа, активацию сертификата, чат и настройку у гостя. Важна граница: нажатие «Оплатить» не доказывает списание; при неопределённом исходе доступна проверка, а не повторная отправка.
